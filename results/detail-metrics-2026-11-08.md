# 상세 지표 소급 분석 — 체크 단위 점수 + 궤적 지표 (2026-11-08)

`analyze.py`로 전 런의 summary.json에서 두 축을 소급 계산했다.

## 방법

- **체크 단위 점수**: 문항 all-or-nothing 대신 체크 통과율로 집계 (코어 32개, 확장 26개, hard 30개 체크).
- **궤적 지표**: call_log에서 호출 수·턴 수·병렬 비율·terminal 비율·샌드박스 밖 절대경로 접근 수, extra에서 api 시간·비캐시 입력 토큰·출력 토큰.
- 한계: 도구 결과는 기록되지 않아 오류·복구 횟수는 소급 불가 — 필요하면 러너가 결과 요약을 record에 남기는 계측을 추가해야 한다 (채점 로직과 무관한 기록 확장).

## 판정 — 변별력이 나오나

**같은 모델 안에서는 점수 변별이 여전히 안 나온다.** 코어 4개 런의 체크 점수가 31/32로 완전히 동점이다. 지표가 뭉툭해서가 아니라, 온도 0에서 같은 입력에 같은 궤적을 밟으니 **측정 대상의 분산 자체가 0에 가깝다.**

대신 두 가지가 실제로 생겼다:

1. **실패의 깊이** — 확장 cal1에서 시나리오 0.0으로 뭉개지던 실패가 체크 단위로는 X4 2/3, X8 1/2, X11 1/2로 구분된다. "완전히 틀림"과 "한 끗 차이"가 갈리는 것 — 모델이 바뀌는 비교에서 여기서 차이가 난다.
2. **행동 프로파일** — 점수가 같아도 일하는 방식이 숫자로 남는다: 세트별 호출/문항 2.7→4.8→6.7 (난이도의 비용 표현), X11의 밖 접근 6회, X18의 병렬률 0.78, N3에서 런마다 밖 접근이 2→3→4로 흔들리는 변동성.

주의: **비캐시 입력 토큰은 비교 지표로 부적합**하다 — 기준선 7,543 vs 0.1.58 837의 차이는 모델이 아니라 캐시 웜업 순서의 함수다.

## 결론

1+2는 변별 장치라기보다 **기록 해상도를 올리는 작업**이었다. 진짜 변별은 (a) 모델이 바뀌는 비교 — UD-IQ1_M 실측이 첫 시험대이며, 이때 비교 축이 점수 1개에서 체크·호출·턴·병렬·밖 접근·시간의 6개로 는다 — 와 (b) 반복 측정을 통한 성공률화에서 온다. 이 지표들은 그 비교를 받을 그릇으로 유지한다.
